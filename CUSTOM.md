# What this fork adds to T3 Code

Branch `custom-v2` is the official T3 Code (`upstream/main`, pingdotgg/t3code) plus the features below.
Every sync merges upstream in with `scripts/custom/sync-upstream.sh`. Upstream's code wins every conflict, except where re-applying a feature listed here needs our side.

**Drop rule.** When upstream ships what a row does, take upstream's version, delete our code, and delete the row. Keep only the part upstream lacks.

Paths are short: `server/`, `web/`, `desktop/` and `mobile/` mean `apps/<name>/src/`; `contracts/`, `shared/`, `client-runtime/`, `provider-core/`, `provider-pi/` and `tailscale/` mean `packages/<name>/src/`.

**Conflict memory.** The script turns on git rerere. It mainly helps when an aborted sync is redone; hunks already resolved in an earlier merge do not conflict again on later merges.

**Rolling back.** A newer build may run database migrations (this sync adds upstream migrations 059–061), so going back to an older build is not guaranteed safe. Copy `~/.t3/userdata/statev2.sqlite` before installing.
